# Changelog

Notable changes to SC500 Academy, newest first. Content corrections that change a
factual claim are listed here with the lesson id. Routine `last_verified` bumps are
not.

## [Unreleased] - beginner-first redesign

Beginner-first in how it explains, certification-first in what it teaches. The scope
did not move - the official study guide still decides what is taught - but every
lesson, lab and question was reworked so someone new to cloud or AI can follow it.
`docs/BEGINNER-FIRST-REDESIGN.md` is the full record; `docs/OBJECTIVE-VALIDATION.md`
records the outline check and every factual correction.

### Added

- **Objective validation.** The study guide was retrieved through the Microsoft Learn
  MCP server on 2026-10-07 and compared with the snapshot: unchanged, 4 domains, 12
  objectives, 87 bullets. New structured manifest `content/skills-measured.json`,
  regenerated by `tools/Update-SkillsManifest.ps1` and checked against the snapshot
  by the validator. New record `docs/OBJECTIVE-VALIDATION.md`.
- **Module 0A · Before we secure the cloud.** 17 foundation primers, each with its own
  anatomy and the official objectives it supports (`supports_objectives`). Exam
  lessons list the primers they rely on. The original Module 0 is now **Module 0B ·
  Safe lab foundations**. The dashboard asks whether you are new to cloud or AI and
  recommends accordingly.
- **Lesson anatomy.** All 18 exam lessons now run: the security problem, in plain
  English, words you need to know, mental model, how it works, why security cares
  (cause and effect, and what the control does not solve), configuration, failure
  modes, hands-on, validate the security outcome, the SC-500 exam lens (with *What
  SC-500 expects you to do*), check yourself, teach it back, key takeaways.
- **Structured comparisons** (`content/comparisons.json`, `assets/js/compare.js`).
  19 comparisons, each option answering the same nine questions, with the SC-500
  takeaway, scenario clues and the trap. Shown in lessons, domain reviews, `#/compare`,
  search, the command palette and the coverage page.
- **Lab anatomy.** All 20 labs now have *Why this lab matters*, an *Architecture*
  diagram, a *Desired security outcome* that Validation must prove, *What just
  happened?*, *Limitations* and a *Completion* checklist confirming the outcome was
  validated and teardown done.
- **Scenario clues on every question** (112), and a named misconception on 109.
- **Applied** and **Retained** progress states, alongside Studied, Practised and
  Knowledge checked. Still no readiness percentage.
- **Validator checks:** lesson, primer and lab anatomy and order; prerequisites;
  `supports_objectives`; scenario clues and `why_not` alignment; comparisons;
  `skills-measured.json` against the snapshot. Each was negative-tested.
- **Accessibility gate** extended to a primer, the comparison pages and a lab with the
  new anatomy.
- **Study posters** (`#/posters`, `posters/`). Five two-sided tabloid posters, each
  with its own header colour and printable as PDF: *Which control?* (19 decisions and
  a scenario decoder), *Who wins?* (evaluation order and precedence), *The AI security
  stack*, *Posture and monitoring*, and *Operate it* (portal paths and PowerShell to
  create and modify; how to revoke, disable or isolate each thing and what that leaves
  running). Generated HTML plus `poster.css`, IBM Plex fonts (OFL), rendered by
  `tools/render-posters.js`, which refuses to write a PDF if any panel overflows its
  page. Every claim was checked by three independent reviewers against Microsoft
  Learn, and all five were checked again on 2026-10-20 by five reviewers, one per
  poster (corrections below).
- **Control map** (`map/index.html`). All 87 official bullets on one interactive map:
  59 controls in nine layers, from who is asking to who responds, joined by 93
  relationships (each stated from both sides), and nine step-by-step walkthroughs of real
  requests. Explore mode shows each control's problem, what it does and does not do, its
  connections, its objectives and the lesson that teaches it. Linked from the sidebar and
  the dashboard; also works on its own.
- **Flowcharts** (`flowcharts/index.html`). Twenty Mermaid flowcharts, rendered with the
  vendored Mermaid in the Academy's theme: two overviews (how the layers fit, where
  security signals go), nine request flows with yes/no decisions and the error each
  control returns, four decision trees (workload identity, private path, network
  control, AI control) and five evaluation orders (Conditional Access, NSGs and security
  admin rules, Azure Policy effects, Azure Firewall rule processing, the network and
  authorization gates for Key Vault and Storage). Every decision restates content the
  lessons already teach; two notes were checked again against Microsoft Learn on
  2026-10-21 (JIT expiry leaves established connections open; Storage firewall rules
  don't apply to private endpoint traffic). Linked from the sidebar, the dashboard and
  the control map.
- **Flowcharts in the lessons.** 17 of the 20 flowcharts also sit in the lesson that
  teaches them, at the point where every piece they show has been covered: 0A-17,
  01-01, 01-03 (two), 02-01, 02-02, 02-03, 02-04 (two), 03-01, 03-03 (two), 03-04,
  03-06, 04-01, 04-02 and 04-04. Request flows close the "How it works" section,
  evaluation orders sit beside the text they restate, and decision trees go in "How
  this is tested". They are generated from the same source as `flowcharts/` and
  marked `%% flowchart: <id>`, so the two never drift. The other three already had an
  equivalent lesson diagram (Conditional Access in 01-01, inbound NSG order in 02-03,
  Azure Firewall rule order in 02-04); those keep their own diagram, now with the same
  red, green and amber outcome outlines. Each lesson flowchart has a one-line key and a
  link to the larger copy with notes; wide ones shrink to fit or scroll sideways
  rather than shrinking the text below about 11px.
- **Case studies** (`#/cases`, `content/cases.json`, `assets/js/cases.js`). Four
  multi-requirement scenarios - a clinical web app, AI in insurance claims, a hub
  network, a SOC build - with 29 questions in exam form: single answer, choose two,
  and drop-down lists. Each question repeats the requirements it tests. **Review my
  design** checks the answers against each other: conflict rules catch combinations
  that each look right alone but break another requirement. Fictional organisations;
  every question joins to an official bullet by id and verbatim text.
- **Break-fix drills** (`#/drills`, `content/drills.json`, `assets/js/drills.js`).
  Eight paper drills: a ticket, simplified evidence (effective routes, NSG rules,
  activity and sign-in logs, a policy assignment, a DCR, a decoded SAS, `az aks
  show`), then four steps that open in order - pick the line that proves the cause,
  name the cause, choose the fix, choose how to prove it worked. Nothing touches
  Azure. Evidence is labelled *Simplified* or *Trimmed*.
- Case questions and drills are recorded in progress (`case:…`, `drill:…`, counted
  as applied), shown per domain on the dashboard, listed in domain reviews under
  *Practise in context*, and counted in a new **Scenarios** column on the coverage
  page. The validator checks both files: objective joins, answer and `why_not`
  alignment, conflict rules pointing at real options, labelled evidence, Microsoft
  Learn sources.

### Changed

- Coverage page: comparisons per bullet, foundation primers per objective, and
  unmapped comparisons reported for review.
- Views with no field card (dashboard, coverage, compare, reviews) give that column
  back to the content on wide screens.
- Long Microsoft Learn URLs, inline code and knowledge-check options wrap on phones
  instead of widening the page (checked at 390 px).
- `docs/STYLE-GUIDE.md`, `docs/CONTRIBUTING.md`, `docs/BUILD-PROMPT.md`,
  `docs/SYLLABUS.md` and the README updated for the new anatomy.

### Fixed - site

- **A deploy did not show until the second or third reload** (`sw.js`, `sc500-v9`).
  The service worker served its cache first and refreshed behind, so the first load
  after every push ran the new `index.html` with the old scripts and lessons: the
  posters, the flowcharts and the new nav links looked missing. Reproduced against a
  GitHub Pages stand-in (same `/SC500-Academy/` path, HTTPS, 10-minute caching): two
  stale loads after a deploy. The worker is now network first with a 4-second
  fallback to the cache, so online readers always get one consistent version and the
  precache still serves the whole guide offline. Checked: a later deploy shows on the
  first load, and lessons and posters still open offline. The switch from `sc500-v8`
  itself still takes one extra reload, because the old worker handles that load.
- **The posters were hard to find.** They were linked only from the sidebar's
  Practice section. They are now on the dashboard's study tools row too, and each card
  on `#/posters` shows a front and back preview (`posters/preview/`, written by
  `tools/render-posters.js`; `--previews` renders them without touching the PDFs).
  The README has a **Study posters** gallery as well: each poster's front, linked to
  its PDF and print page, plus the all-in-one PDF and printing notes.

### Fixed - content corrected against Microsoft Learn

Full list with sources in `docs/OBJECTIVE-VALIDATION.md` §6. Highlights:

- **Lab 03-06 Part 5.4** restricted the backend to the `ApiManagement` service tag,
  which lists API Management's control-plane addresses and would not have admitted
  the Basic v2 gateway. It now uses the gateway's managed identity and App Service
  authentication restricted to that identity.
- **04-04 and quiz 04-04:** MailItemsAccessed is part of Audit (Standard) mailbox
  auditing for E3/E5 users, not an Audit (Premium)-only event. Retention wording now
  uses the analytics tier and data lake model throughout lab 04-04.
- **04-05 and quiz 04-05:** new Security Copilot instances default contributor
  access to the Recommended Microsoft Security roles group; Everyone is legacy. E5/E7
  include capacity (400 SCUs a month per 1,000 licences).
- **01-03, 04-01:** regulatory compliance standards need any Defender plan except
  Servers Plan 1 or APIs Plan 1, not specifically Defender CSPM.
- **03-03:** AI discovery and posture come from Defender CSPM, not the Defender for AI
  Services plan; Foundry guardrails replace the old content-filter model; agent
  security moved to Microsoft Agent 365 on 1 July 2026.
- **03-04, 03-05, 03-06, 04-01, 04-03:** Azure Disk Encryption retirement, Docker
  Content Trust removal, ACR admin account disabled by default, WAF overrides and
  exclusions reapplied after a version change, EASM billing on Approved Inventory
  only, WEF data landing in WindowsEvent.

- **Fact-check of the posters** exposed errors the Academy text shared, now fixed:
  Virtual WAN Forced Tunnel is a private routing policy with `0.0.0.0/0` in
  additional prefixes and no internet policy (02-03, lab, quiz q6); Defender portal
  table settings are under **Microsoft Sentinel → Configuration → Tables** (04-02 to
  04-04, labs); Azure SQL refuses Entra-only authentication until an Entra admin is
  set (lab 02-02); `-ScmSiteUseMainSiteRestrictionConfig` is a switch (lab 03-06);
  the SAS expiration policy can **Block**, not only log (02-01, lab, quiz q1);
  `estimate-prompt-tokens` *can* stop over-limit calls, not guarantees it (03-03,
  lab, quiz q2); the Databases plan switch turns on all four types (02-02, quiz q4);
  declining Arc leaves agentless scanning in place (04-01, quiz q5); Sentinel
  onboarding roles, commitment-tier and analytics-retention details (04-02, 04-04);
  the Defender for AI Services DeployIfNotExists policies (03-03); and the blast
  radius data lake prerequisite (03-02).
- **Second poster fact-check (2026-10-20)** found errors the Academy text shared:
  the Defender XDR connector **disconnects** the per-product alert connectors itself,
  and its alerts and incidents are ingested free - the risk is duplicate *incidents*
  from Microsoft incident creation rules, not double ingestion or double billing
  (04-02, 04-03, labs 04-02 and 04-03, quiz 04-03 q1 rewritten); there are two
  secure score models, the classic benchmark score in the Azure portal and the
  risk-based Cloud Secure Score in the Defender portal (04-01, quiz 04-01 q3, A11);
  transformation filtering is free only for Analytics tables in Sentinel workspaces
  (04-03, lab 04-03); a Security Copilot agent identity is offered only for
  Microsoft-built agents (04-05); a WAF rule set change resets rule-level tuning
  when made in the portal, while scripts and templates can carry it across (03-06,
  lab, quiz q3, A3); workload identity federation also works on a user-assigned
  managed identity (comparison, flashcard c107); and Defender real-time protection
  for agents can block, so "only guardrails or the gateway block" was too narrow
  (comparison).
- **Independent fact-check of the new lab text** corrected: Private Access licensing
  (Entra Private Access or Entra Suite, not "Global Secure Access licensing"),
  Restricted Content Discovery discoverability, exemptions versus exclusions, guardrail
  actions for agents, and Log Analytics workspace recovery. The Defender for
  Containers billing unit, which Microsoft Learn does not state, is no longer given.

## Certification-first redesign (commit 9fa07ce)

The whole site was reorganised around one question: what does a learner need, right
now, to pass SC-500? `docs/UX-REDESIGN.md` has the full record: what maps to what,
the verification run, and the backlog.

### Added

- **Learning dashboard.** It shows a Continue-learning recommendation, and per-domain
  Studied, Practised and Knowledge-checked counts per official sub-objective, with an
  objective status table. There is deliberately no readiness percentage.
- **Consistent lesson stages:** Orient, Learn, Visualize, Distinguish, Practice,
  Check, Review. Each lesson also gets:
  - breadcrumbs and a stage rail;
  - "What you need to know", listing the verbatim sub-objectives with their outline
    positions;
  - prerequisites marked with whether each one has been studied;
  - the SC-500 Exam Lens;
  - the A6 comparisons shown inline;
  - a lab card;
  - a Next-step block.
- **Knowledge checks answered one question at a time.** After each answer the site
  shows the correct answer, why, why not each other option, and the objective. Every
  answer is recorded per question.
- **Domain review** (`#/domain/<id>`), **Exam prep** (`#/prep`), including "Review
  later" bookmarks and "Needs review", and **Objective coverage** (`#/coverage`),
  derived live from the skills snapshot.
- **Lab mode.** A distinct header showing cost, time, resources created and the
  teardown requirement, plus a part tracker you can resume from.
- **Domain colour system.** Four exam-domain colours, contrast-checked in both
  themes, always paired with an icon shape and a text label.
- **Thirteen new questions,** closing every untested sub-objective. There are now 109
  questions, and every one carries per-option `why_not` notes.
- **Seven diagrams:** 00-02 (the PIM activation path), 01-01, 01-02, 02-03, 02-04
  (twice, including Azure Firewall's rule-processing order) and 04-03. They are
  domain-coloured, screen-reader labelled and legible on phones.
- **Official Microsoft training mapped to every objective**
  (`content/official-training.json`). It covers Course SC-500T00-A's 12 learning paths
  and Microsoft's 16 labs, all verified against Microsoft's own sources.
- **Official training at module level.**
  - All 63 Microsoft Learn modules of SC-500T00-A are mapped to the lessons they
    serve, and so are Microsoft's 16 labs.
  - Each lesson lists its own modules and labs, not the whole objective's.
  - The drift poll compares exact module lists.
- **New CI:** an accessibility gate (`.github/workflows/a11y.yml`), and a third
  outline-drift poll that watches the linked official training.
- **README rewritten for learners.** It now covers purpose, how to use the Academy
  with Microsoft Learn and Course SC-500T00-A, a table of contents linking every
  lesson, lab, appendix and study tool, a study plan, and a short guide to the labs.
  Repository layout and CI moved to `docs/CONTRIBUTING.md`.
- **Repository housekeeping:** issue forms, a pull request template, this changelog,
  and `SECURITY.md`.

### Changed

- The investigation note (`forensic_relevance`) moved from the top of each lesson to
  a collapsed "Beyond the exam" panel. It is useful, but not measured.
- Mermaid loads only on pages that contain a diagram, rather than on every visit
  (3.5 MB). Measured on a first visit over simulated slow 4G, gzipped as on GitHub
  Pages:
  - the dashboard is ready in 3.2 s instead of 7.5 s;
  - a lesson is ready in 2.0 s instead of 7.8 s;
  - about 70% less is downloaded.

  See `docs/UX-REDESIGN.md` section 13.
- Below 1180 px, the field card now sits below the lesson instead of above it.
- Search results show their domain and objective, and match common acronyms.
- **Domain colours are now exclusive.** Orange means Domain 4 and nothing else.
  - The three other oranges beside it - Medium cost, Preview status, Needs review -
    become one "caution" amber: `#efd36b` dark, `#4f3c00` light.
  - Low cost moves from `#0078d4`, identical to Domain 1 in light mode, to neutral
    grey.
  - Values were chosen by measurement (tokens.css, RESERVED HUES). Normal-vision
    distance from Domain 4 is now 32.7 / 28.7 CIEDE2000, up from 17.7 / 11.5.
  - Worst case under simulated protanopia or deuteranopia is 14.5 / 7.1, up from
    9.7 / 0.2.
- 01-03-q5 rewritten. The old premise put `Microsoft.KeyVault/vaults/secrets/read` in
  NotActions. That is a control-plane action which views a secret's properties, not
  its value, so the likeliest explanation was missing from the options.
  - The new version excludes the data action that returns the value,
    `secrets/getSecret/action`, in NotDataActions. It keeps both original
    explanations as the correct answers.
  - The old premise becomes a wrong option, with a why-not note.
  - Lesson 01-03's matching self-check and its RBAC paragraph were aligned. Two
    Sources entries were added: Azure role definitions, and the built-in roles for
    Security.
  - All of this was checked against Microsoft's role and permission reference.
- 01-02-q1: option C now names a CanNotDelete lock. "A resource lock" also covered
  ReadOnly, which would have made the option arguably correct.

### Fixed

- The mock exam, flashcards, retention review, verification watchlist and offline
  support, all committed in 364e215, were never loaded or routed. They are now
  reachable.
- Appendices A6-A11 were missing from the manifest. They are now listed, and A7 is
  kept by the maintainer's decision.
- Prerequisite links were broken: the front-matter parser kept the closing quote, so
  links went to `#/module/00-00"`.
- 129 internal links resolved to the dashboard. Relative links are now resolved

- `404.html` redirected to the domain root instead of the Academy.
- Light-mode Preview badge contrast was 3.96:1, below the AA minimum of 4.5:1; it

  verification watchlist and the cost planner.
- The verification watchlist table had an empty header cell (axe
  `empty-table-header`). It now has a screen-reader name.
- README: removed the claim that Microsoft had published no learning path. Course
  SC-500T00-A has existed since at least 2026-07-30.
- README: removed the claim that every sub-objective maps to exactly one module. PIM
  is also practised in Module 0.

- The validator failed `main` with 29 false-positive errors, so CI was red on every
  push. Three rules in `tools/Test-GuideContent.ps1` were corrected:
  - Module 0 is no longer held to the exam-lesson section skeleton.
  - Module 0 no longer "owns" a sub-objective. That rule had blocked any PIM
    question in 01-01.
  - The snapshot parser counts only bullets under an objective heading.

  It now passes with no issues. The last warning was lab 00-01 having no numbered
  part. Its two methods now sit under `## Part 1`, headings only, which also gives
  that lab its part tracker.

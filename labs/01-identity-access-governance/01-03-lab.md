# Lab 01-03 - Governance and Regulatory Compliance

**Objective:** Implement governance to enforce security and regulatory compliance
**Estimated cost:** Low. Policy, locks, roles, and an empty Recovery Services vault
are free. **Defender CSPM bills at subscription scope** if you enable it for Part 2 -
set it back to Free in teardown, same session.
**Licensing required:** Azure subscription; Microsoft Entra ID P1 or higher for the
Entra custom role in Part 5.
**Time:** ~180 minutes. Seven independent parts; stop at any boundary.

> Complete **Module 0** before running this lab. Activate your roles through PIM;
> do not run labs with standing Global Administrator.
>
> **Do not lock the immutable vault in Part 6.** Locking is irreversible, in the same
> family as Key Vault purge protection in [01-02](./01-02-lab.md).

## Prerequisites

- PIM activation: **Owner**, or **Contributor + User Access Administrator**, at
  subscription scope. Locks and role definitions need
  `Microsoft.Authorization/*/write`, which Contributor alone does not have.
- **Privileged Role Administrator** in Entra, for Part 5b.
- Modules: `Az.Resources`, `Az.PolicyInsights`, `Az.Security`, `Az.Storage`,
  `Az.RecoveryServices`, `Microsoft.Graph.Identity.Governance`.

```powershell
$Location = 'canadacentral'
$LabId    = '01-03'
$Rg       = "rg-sc500-lab-$LabId"
$SubId    = (Get-AzContext).Subscription.Id
$SubScope = "/subscriptions/$SubId"

New-AzResourceGroup -Name $Rg -Location $Location -Tag @{ 'sc500-module' = $LabId } -Force
```

> **Version caution.** The Az policy cmdlets changed parameter shapes across recent
> major versions. If a command below rejects a parameter, run
> `Get-Command New-AzPolicyAssignment -Syntax` against your installed module rather
> than guessing.

## Part 1 - Azure Policy: audit, then deny, then remediate

### Method A - Portal

1. **Azure portal** → **Policy** → **Definitions**. Filter by category **Storage**,
   find *Secure transfer to storage accounts should be enabled*. Read its JSON -
   note the `effect` parameter with an `Audit` default.
2. **Assignments** → **Assign policy**. Scope `rg-sc500-lab-01-03`, that definition,
   effect **Audit**. Create.
3. **Definitions** → **+ Policy definition** to create a custom one. Definition
   location: your subscription. Name `sc500-01-03-require-module-tag`. Paste the rule
   from Method B. Category: create new, `SC500`. Save.
4. Assign the custom definition to the resource group with effect **Deny**.
5. **Compliance** → open the assignment. It may show *Not started* until the first
   evaluation. Use **Compliance scan** to trigger one.

### Method B - PowerShell

```powershell
# --- Built-in, as Audit -------------------------------------------------------
$builtIn = Get-AzPolicyDefinition | Where-Object {
    $_.Properties.DisplayName -eq 'Secure transfer to storage accounts should be enabled'
}

New-AzPolicyAssignment -Name 'sc500-0103-secure-transfer' `
                       -DisplayName 'SC500 01-03 audit secure transfer' `
                       -PolicyDefinition $builtIn `
                       -Scope "$SubScope/resourceGroups/$Rg" `
                       -PolicyParameterObject @{ effect = 'Audit' }

# --- Custom definition: deny anything without the module tag ------------------
$rule = @'
{
  "if": {
    "allOf": [
      { "field": "type", "notEquals": "Microsoft.Resources/deployments" },
      { "field": "tags['sc500-module']", "exists": "false" }
    ]
  },
  "then": { "effect": "[parameters('effect')]" }
}
'@

$params = @'
{
  "effect": {
    "type": "String",
    "allowedValues": [ "Audit", "Deny", "Disabled" ],
    "defaultValue": "Audit"
  }
}
'@

$custom = New-AzPolicyDefinition -Name 'sc500-01-03-require-module-tag' `
                                 -DisplayName 'SC500 lab resources must carry sc500-module tag' `
                                 -Policy $rule `
                                 -Parameter $params `
                                 -Mode Indexed `
                                 -SubscriptionId $SubId

New-AzPolicyAssignment -Name 'sc500-0103-require-tag' `
                       -PolicyDefinition $custom `
                       -Scope "$SubScope/resourceGroups/$Rg" `
                       -PolicyParameterObject @{ effect = 'Deny' }
```

### 1.3 Prove `Deny` acts on the request, not on the estate

```powershell
$sa = "stsc500$((Get-Random -Maximum 99999))"

# Untagged -> blocked by your Deny assignment. Read the error; it names the policy.
New-AzStorageAccount -ResourceGroupName $Rg -Name $sa -Location $Location `
                     -SkuName Standard_LRS

# Tagged and non-compliant on HTTPS -> allowed, because that assignment is only Audit
New-AzStorageAccount -ResourceGroupName $Rg -Name $sa -Location $Location `
                     -SkuName Standard_LRS `
                     -Tag @{ 'sc500-module' = $LabId } `
                     -EnableHttpsTrafficOnly $false

Start-AzPolicyComplianceScan -ResourceGroupName $Rg
Get-AzPolicyState -ResourceGroupName $Rg |
    Select-Object PolicyDefinitionName, ComplianceState, ResourceId | Format-Table -AutoSize
```

The second account exists and is non-compliant. **That is the point of the part:**
`Deny` stopped a request; nothing retroactively fixed the resource that a different
assignment merely audits.

### 1.4 Remediate with `Modify`

```powershell
# Modify needs an identity and a location
$modifyRule = @'
{
  "if": { "field": "type", "equals": "Microsoft.Storage/storageAccounts" },
  "then": {
    "effect": "modify",
    "details": {
      "roleDefinitionIds": [
        "/providers/Microsoft.Authorization/roleDefinitions/17d1049b-9a84-46fb-8f53-869881c3d3ab"
      ],
      "operations": [
        { "operation": "addOrReplace", "field": "tags['sc500-remediated']", "value": "true" }
      ]
    }
  }
}
'@

$mod = New-AzPolicyDefinition -Name 'sc500-01-03-tag-remediated' `
                              -DisplayName 'SC500 tag storage accounts as remediated' `
                              -Policy $modifyRule -Mode Indexed -SubscriptionId $SubId

$modAssign = New-AzPolicyAssignment -Name 'sc500-0103-modify-tag' `
                                    -PolicyDefinition $mod `
                                    -Scope "$SubScope/resourceGroups/$Rg" `
                                    -IdentityType SystemAssigned `
                                    -Location $Location

# The identity needs its role BEFORE remediation will do anything
Start-Sleep 30
New-AzRoleAssignment -ObjectId $modAssign.Identity.PrincipalId `
                     -RoleDefinitionName 'Storage Account Contributor' `
                     -Scope "$SubScope/resourceGroups/$Rg"

Start-AzPolicyRemediation -Name 'sc500-0103-remediate' `
                          -PolicyAssignmentId $modAssign.Id `
                          -ResourceGroupName $Rg

(Get-AzStorageAccount -ResourceGroupName $Rg -Name $sa).Tags
```

> The GUID above is the built-in **Storage Account Contributor** role definition ID,
> which `Modify` requires you to declare inside the policy. Look it up with
> `(Get-AzRoleDefinition -Name 'Storage Account Contributor').Id` rather than trusting
> a pasted GUID.

### 1.5 Exemption versus exclusion

Create an **exemption** for the storage account against your audit assignment, with a
justification and an expiry, then find it in **Policy** → **Exemptions**. Compare with
setting an exclusion on the assignment's scope: the exclusion leaves no record of why.

## Part 2 - Defender for Cloud standards and regulatory compliance

**Cost gate.** Step 3 requires Defender CSPM. Enable it, look, disable it.

1. **Defender for Cloud** → **Environment settings** → your subscription →
   **Security policies**. The **Microsoft cloud security benchmark** is applied by
   default. Open it and note that it is an Azure Policy initiative.
2. **Regulatory compliance**. With foundational CSPM only, MCSB is what you see.
   Read one control and follow it to the recommendations that evidence it.
3. Enable **Defender CSPM** (`Set-AzSecurityPricing -Name 'CloudPosture' -PricingTier 'Standard'`),
   then **Security policies** → **Add more standards** and assign one framework.
   Return to **Regulatory compliance** and read the same control through the new
   standard's mapping.
4. **Recommendations** → pick one affecting your lab storage account → read the
   remediation steps → note whether it offers **Fix**, and connect that back to the
   remediation task you ran in 1.4.
5. Create an **exemption** on a recommendation with a justification. Confirm it
   appears in the compliance view rather than vanishing.

## Part 3 - Resource locks

### Method A - Portal

1. Resource group `rg-sc500-lab-01-03` → **Locks** → **Add** → name
   `sc500-0103-nodelete`, type **Delete**. OK.
2. Try to delete the resource group. Read the error.
3. Add a second lock, type **Read-only**, on the **storage account** only.
4. With the read-only lock in place, open the storage account → **Access keys** →
   **Show keys**. It fails. Note why: listing keys is a POST operation, not a read.
5. Remove the read-only lock.

### Method B - PowerShell

```powershell
New-AzResourceLock -LockName 'sc500-0103-nodelete' -LockLevel CanNotDelete `
                   -ResourceGroupName $Rg -Force

Remove-AzResourceGroup -Name $Rg -Force        # fails, by design

New-AzResourceLock -LockName 'sc500-0103-readonly' -LockLevel ReadOnly `
                   -ResourceGroupName $Rg -ResourceName $sa `
                   -ResourceType 'Microsoft.Storage/storageAccounts' -Force

Get-AzStorageAccountKey -ResourceGroupName $Rg -Name $sa     # fails under ReadOnly

Remove-AzResourceLock -LockName 'sc500-0103-readonly' -ResourceGroupName $Rg `
                      -ResourceName $sa `
                      -ResourceType 'Microsoft.Storage/storageAccounts' -Force
```

Leave the `CanNotDelete` lock in place for now. Teardown will make you remove it,
which is the habit worth building.

## Part 4 - Built-in role assignments

```powershell
$sp = Get-AzADServicePrincipal -DisplayName 'sc500-01-01-app-reg'

New-AzRoleAssignment -ObjectId $sp.Id -RoleDefinitionName 'Reader' `
                     -Scope "$SubScope/resourceGroups/$Rg"

# Everything the principal holds, at every scope - the union is what matters
Get-AzRoleAssignment -ObjectId $sp.Id |
    Select-Object RoleDefinitionName, Scope | Format-Table -AutoSize

# Subscription-scope assignments: the review that finds real overprivilege
Get-AzRoleAssignment -Scope $SubScope |
    Where-Object { $_.Scope -eq $SubScope } |
    Select-Object DisplayName, ObjectType, RoleDefinitionName | Format-Table -AutoSize
```

## Part 5 - Custom roles

### 5a. Azure custom role

```powershell
$role = Get-AzRoleDefinition -Name 'Reader'
$role.Id              = $null
$role.IsCustom        = $true
$role.Name            = 'SC500 Lab Storage Key Reader'
$role.Description     = 'Read storage accounts and list keys. Nothing else.'
$role.Actions.Add('Microsoft.Storage/storageAccounts/listkeys/action')
$role.AssignableScopes.Clear()
$role.AssignableScopes.Add($SubScope)

$custRole = New-AzRoleDefinition -Role $role
$custRole | Format-List Name, IsCustom, Actions, NotActions, AssignableScopes
```

Note `AssignableScopes` is the subscription, not tenant root. Assign it to the test
principal at resource group scope and confirm it can list keys and nothing else.

### 5b. Entra custom role

Different system, different permission catalogue, needs Entra ID P1 or higher.

```powershell
Connect-MgGraph -Scopes 'RoleManagement.ReadWrite.Directory'

New-MgRoleManagementDirectoryRoleDefinition -BodyParameter @{
    displayName = 'sc500-01-03-app-reader'
    description = 'Read application registrations. Directory scope only.'
    isEnabled   = $true
    rolePermissions = @(
        @{ allowedResourceActions = @('microsoft.directory/applications/standard/read') }
    )
}
```

Confirm in **Entra admin center** → **Roles & admins** → **All roles**, filtered to
custom. Nothing you did in 5a appears there, and nothing from 5b appears in
`Get-AzRoleDefinition`. Two systems.

## Part 6 - Azure Backup security features

An empty Recovery Services vault is free. Protect nothing in this lab.

### Method A - Portal

1. **Recovery Services vaults** → **Create** → resource group
   `rg-sc500-lab-01-03`, name `rsv-sc500-0103`.
2. **Properties** → **Security settings** → **Update**. Confirm soft delete is on,
   set **enhanced soft delete** retention, and read the **always-on** option -
   **do not enable it here**, it is irreversible.
3. **Properties** → **Immutable vault** → set to **Enabled**. **Leave it Unlocked.**
   Read the warning about locking.
4. **Multi-user authorization**: create a **Resource Guard**
   (**Resource Guards** → **Create**), then on the vault set **Multi-User
   Authorization** → **Protected by Resource Guard** and select it.
5. Attempt to disable soft delete on the vault. It is now gated by the guard.

### Method B - PowerShell

```powershell
$rsv = New-AzRecoveryServicesVault -Name 'rsv-sc500-0103' `
                                   -ResourceGroupName $Rg -Location $Location

Set-AzRecoveryServicesVaultProperty -VaultId $rsv.ID -SoftDeleteFeatureState Enable
Get-AzRecoveryServicesVaultProperty -VaultId $rsv.ID | Format-List
```

> Immutability state and MUA wiring are portal-driven above because the cmdlet surface
> for them moves between `Az.RecoveryServices` and `Az.DataProtection` versions. Check
> `Get-Command -Module Az.RecoveryServices *Vault*` against what you have installed
> before scripting them.

**The point of Part 6 is placement, not clicks.** Your Resource Guard is in the same
subscription as the vault, owned by you. Write down what that configuration actually
protects against, and what it does not.

## Part 7 - Infrastructure as code

The strongest version of this objective is not a scanner. It is your `Deny`
assignment from Part 1 rejecting a template.

```powershell
@'
param location string = resourceGroup().location
param saName string

resource sa 'Microsoft.Storage/storageAccounts@2023-01-01' = {
  name: saName
  location: location
  sku: { name: 'Standard_LRS' }
  kind: 'StorageV2'
  properties: { supportsHttpsTrafficOnly: false }
  // no tags - deliberately non-compliant with sc500-01-03-require-module-tag
}
'@ | Set-Content .\sc500-0103-noncompliant.bicep

New-AzResourceGroupDeployment -ResourceGroupName $Rg `
                              -TemplateFile .\sc500-0103-noncompliant.bicep `
                              -saName "stsc500$((Get-Random -Maximum 99999))"
```

The deployment fails and the error names the policy assignment. A template author who
never read your standard is still bound by it, because the control lives in the
platform rather than in the template.

Now add the tag to the Bicep file and redeploy. It succeeds, and the storage account
is still non-compliant on secure transfer - because that assignment is `Audit`. Both
halves of Part 1 reappear here.

**Optional, portal only:** **Defender for Cloud** → **Environment settings** →
**Add environment** → **GitHub**, and connect your `SC500-Academy` repository. The
Microsoft Security DevOps action then scans IaC in the pipeline, with findings in
Defender for Cloud and, if enabled, as pull request annotations. Remember that DevOps
recommendations do not affect secure score.

## Validation

```powershell
# 1. Policy: two assignments, one Deny, one Audit, plus the Modify assignment
Get-AzPolicyAssignment -Scope "$SubScope/resourceGroups/$Rg" |
    Select-Object Name, @{n='Effect';e={$_.Properties.Parameters.effect.value}}

# 2. Compliance reflects reality
Start-AzPolicyComplianceScan -ResourceGroupName $Rg
Get-AzPolicyState -ResourceGroupName $Rg |
    Group-Object ComplianceState | Select-Object Name, Count

# 3. Locks
Get-AzResourceLock -ResourceGroupName $Rg | Select-Object Name, Properties

# 4. Custom role exists and is scoped to the subscription, not tenant root
Get-AzRoleDefinition -Custom | Select-Object Name, AssignableScopes

# 5. Vault security properties
Get-AzRecoveryServicesVaultProperty -VaultId $rsv.ID | Format-List
```

### Portal validation

**Defender for Cloud** → **Regulatory compliance**. Find a control that your Part 1
policy contributes to. That path - policy definition to assignment to recommendation
to framework control - is the mental model the exam is testing, and it is easier to
believe once you have watched one of your own rules appear at the far end of it.

## Teardown

**Mandatory.** The locks come off first or nothing else works.

### 1. Resources
- [ ] Remove the `CanNotDelete` lock **before** deleting anything:
      ```powershell
      Get-AzResourceLock -ResourceGroupName $Rg |
          ForEach-Object { Remove-AzResourceLock -LockId $_.LockId -Force }
      ```
- [ ] `Remove-AzResourceGroup -Name rg-sc500-lab-01-03 -Force` (storage account,
      Recovery Services vault, Resource Guard)
- [ ] Delete `.\sc500-0103-noncompliant.bicep` from your working directory

### 2. Subscription scope
- [ ] `Set-AzSecurityPricing -Name 'CloudPosture' -PricingTier 'Free'` if you enabled
      it in Part 2
- [ ] Remove the compliance standard assigned in Part 2, if any
- [ ] Remove policy assignments, then exemptions, then definitions - in that order:
      ```powershell
      Get-AzPolicyAssignment -Scope "$SubScope/resourceGroups/$Rg" |
          Where-Object Name -like 'sc500-0103*' |
          ForEach-Object { Remove-AzPolicyAssignment -Id $_.Id }

      Get-AzPolicyDefinition -SubscriptionId $SubId -Custom |
          Where-Object { $_.Name -like 'sc500-01-03*' } |
          ForEach-Object { Remove-AzPolicyDefinition -Id $_.Id -Force }
      ```
- [ ] Remove the role assignment held by the `Modify` assignment's managed identity -
      deleting the assignment orphans it
- [ ] `Remove-AzRoleDefinition -Id $custRole.Id -Force`
- [ ] Remove the Reader assignment created in Part 4

### 3. Directory scope
- [ ] Delete the Entra custom role from 5b:
      ```powershell
      Get-MgRoleManagementDirectoryRoleDefinition -Filter "displayName eq 'sc500-01-03-app-reader'" |
          ForEach-Object { Remove-MgRoleManagementDirectoryRoleDefinition -UnifiedRoleDefinitionId $_.Id }
      ```

### 4. Soft-deleted remains
- [ ] The Recovery Services vault protected nothing, so it deletes cleanly. Had you
      backed up an item, soft delete would hold it and the vault would refuse to
      delete until the retained items were handled.

### 5. Access
- [ ] Deactivate every PIM role activated for this lab

### 6. Verify
- [ ] `Get-AzPolicyAssignment -Scope $SubScope | Where-Object Name -like 'sc500-*'`
      returns nothing
- [ ] `Get-AzRoleDefinition -Custom` shows no SC500 roles
- [ ] `Get-AzResourceLock -ResourceGroupName $Rg` errors (group is gone)
- [ ] `Get-AzSecurityPricing | Where-Object PricingTier -eq 'Standard'` is empty
- [ ] Cost Management shows no new daily run rate tomorrow

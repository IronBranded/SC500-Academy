# Lab 02-04 - Private Access and Network Perimeter

**Objective:** Implement security for Azure network services
**Estimated cost:** **HIGH.** The largest hourly spend outside Security Copilot. Azure Firewall bills hourly from
the moment deployment completes, plus a per-gigabyte data processing charge, whether or
not traffic flows. Budget for the wall-clock time you keep it, not the time you spend
using it. Private endpoints are hourly but cheap; a B1s VM is pennies.
**Licensing required:** Azure subscription. **Part 5 additionally requires Global
Secure Access licensing, which Microsoft 365 E5 does not include.**
**Time:** ~180 minutes. Parts 1-4 must be done in one sitting.

> Complete **Module 0** before running this lab. Activate your roles through PIM;
> do not run labs with standing Global Administrator.
>
> **Start a timer when the firewall finishes deploying.** Deployment takes 10-20
> minutes and billing starts the moment it lands, not when you start testing. If you
> are interrupted, delete the firewall and start again another day - it deploys again
> in twenty minutes and the rules are in a policy object that costs nothing to keep.

## Part 1 - Topology (do this before the firewall exists)

Build everything that does not bill by the hour first, so the firewall's clock starts
as late as possible.

```powershell
# Hub with the two named subnets Azure Firewall requires
$fwSub  = New-AzVirtualNetworkSubnetConfig -Name 'AzureFirewallSubnet' -AddressPrefix '10.40.0.0/26'
$peSub  = New-AzVirtualNetworkSubnetConfig -Name 'snet-pe'             -AddressPrefix '10.40.1.0/24'
$hub = New-AzVirtualNetwork -Name 'vnet-sc500-0204-hub' -ResourceGroupName $Rg `
                            -Location $Location -AddressPrefix '10.40.0.0/16' `
                            -Subnet $fwSub,$peSub -Tag @{ 'sc500-module' = $LabId }

# Spoke with a workload subnet
$wlSub = New-AzVirtualNetworkSubnetConfig -Name 'snet-workload' -AddressPrefix '10.41.1.0/24'
$spoke = New-AzVirtualNetwork -Name 'vnet-sc500-0204-spoke' -ResourceGroupName $Rg `
                              -Location $Location -AddressPrefix '10.41.0.0/16' `
                              -Subnet $wlSub -Tag @{ 'sc500-module' = $LabId }

Add-AzVirtualNetworkPeering -Name 'hub-to-spoke' -VirtualNetwork $hub -RemoteVirtualNetworkId $spoke.Id | Out-Null
Add-AzVirtualNetworkPeering -Name 'spoke-to-hub' -VirtualNetwork $spoke -RemoteVirtualNetworkId $hub.Id | Out-Null

# One B1s VM in the spoke, no public IP, no Bastion.
# Every test runs through Invoke-AzVMRunCommand - no session, no exposed port.
$cred = Get-Credential -Message 'Local admin for the lab VM (not stored anywhere)'
$vm = New-AzVM -ResourceGroupName $Rg -Location $Location -Name 'vm-sc500-0204' `
               -VirtualNetworkName 'vnet-sc500-0204-spoke' -SubnetName 'snet-workload' `
               -Size 'Standard_B1s' -Image 'Ubuntu2204' -Credential $cred `
               -PublicIpAddressName $null -OpenPorts @()

# Storage account, public access on for now - Part 2 closes it
$sa = New-AzStorageAccount -ResourceGroupName $Rg -Name $Sa -Location $Location `
                           -SkuName Standard_LRS -Kind StorageV2 `
                           -AllowBlobPublicAccess $false -MinimumTlsVersion TLS1_2 `
                           -Tag @{ 'sc500-module' = $LabId }
```

## Part 2 - Private endpoint, and the door it does not close

### Method A - Portal

1. Storage account → **Networking** → **Private endpoint connections** → **Private
   endpoint**.
2. Resource group `rg-sc500-lab-02-04`, name `pe-sc500-0204-blob`, target sub-resource
   **blob**.
3. Virtual network `vnet-sc500-0204-hub`, subnet `snet-pe`.
4. **DNS** tab: integrate with a private DNS zone - accept
   `privatelink.blob.core.windows.net`. Create.
5. Open the private DNS zone → **Virtual network links**. The hub is linked. **The
   spoke is not.** Add a link for the spoke manually.

### Method B - PowerShell

```powershell
$peSubnet = (Get-AzVirtualNetwork -Name 'vnet-sc500-0204-hub' -ResourceGroupName $Rg).Subnets |
            Where-Object Name -eq 'snet-pe'

$conn = New-AzPrivateLinkServiceConnection -Name 'plsc-blob' `
            -PrivateLinkServiceId $sa.Id -GroupId 'blob'

$pe = New-AzPrivateEndpoint -ResourceGroupName $Rg -Name 'pe-sc500-0204-blob' `
          -Location $Location -Subnet $peSubnet -PrivateLinkServiceConnection $conn

$zone = New-AzPrivateDnsZone -ResourceGroupName $Rg -Name 'privatelink.blob.core.windows.net'

# Link BOTH virtual networks. The spoke is the one people forget.
foreach ($v in @($hub, $spoke)) {
    New-AzPrivateDnsVirtualNetworkLink -ResourceGroupName $Rg -ZoneName $zone.Name `
        -Name "link-$($v.Name)" -VirtualNetworkId $v.Id | Out-Null
}

$cfg = New-AzPrivateDnsZoneConfig -Name 'blob' -PrivateDnsZoneId $zone.ResourceId
New-AzPrivateDnsZoneGroup -ResourceGroupName $Rg -PrivateEndpointName $pe.Name `
                          -Name 'zg' -PrivateDnsZoneConfig $cfg
```

### 2.3 Prove all three of the things that catch people

```powershell
# From inside the VNet: resolves to a private address
Invoke-AzVMRunCommand -ResourceGroupName $Rg -VMName 'vm-sc500-0204' `
    -CommandId 'RunShellScript' `
    -ScriptString "getent hosts $Sa.blob.core.windows.net"
```

```powershell
# From your laptop, outside the VNet: still the PUBLIC address, by design
Resolve-DnsName "$Sa.blob.core.windows.net" | Select-Object Name, Type, IPAddress
```

```powershell
# And the public endpoint is still wide open, because a private endpoint
# does not close it. Close it explicitly:
Update-AzStorageAccountNetworkRuleSet -ResourceGroupName $Rg -Name $Sa `
                                      -DefaultAction Deny -Bypass None
```

Three separate facts, none of which the portal warns you about: private DNS is the
implementation, outside resolution stays public, and **the public door stays open until
you shut it yourself.**

Now break it deliberately - unlink the private DNS zone from the spoke and re-run the
VM resolution. The name resolves publicly, the storage firewall denies it, and the
failure looks like an authorization problem rather than a DNS one. Relink it.

## Part 3 - Azure Firewall

> **Cost clock starts here.** Note the time. Target: everything below inside 90
> minutes, then delete.

### 3.1 Policy first, firewall second

A firewall policy is a free object. Build the rules before you deploy the thing that
bills.

```powershell
$pol = New-AzFirewallPolicy -Name 'afwp-sc500-0204' -ResourceGroupName $Rg `
                            -Location $Location `
                            -ThreatIntelMode 'Deny'      # Alert is the default

# One rule collection group holding both a network and an application rule collection
$appRule = New-AzFirewallPolicyApplicationRule -Name 'allow-microsoft' `
               -SourceAddress '10.41.0.0/16' `
               -TargetFqdn '*.microsoft.com','*.ubuntu.com' `
               -Protocol 'http:80','https:443'

$appRc = New-AzFirewallPolicyFilterRuleCollection -Name 'rc-app' -Priority 300 `
             -Rule $appRule -ActionType 'Allow'

$netRule = New-AzFirewallPolicyNetworkRule -Name 'allow-dns' `
               -SourceAddress '10.41.0.0/16' -DestinationAddress '*' `
               -DestinationPort 53 -Protocol UDP

$netRc = New-AzFirewallPolicyFilterRuleCollection -Name 'rc-net' -Priority 200 `
             -Rule $netRule -ActionType 'Allow'

New-AzFirewallPolicyRuleCollectionGroup -Name 'rcg-baseline' -Priority 200 `
    -RuleCollection $appRc,$netRc -FirewallPolicyObject $pol
```

### 3.2 Deploy, and start the clock

```powershell
$fwIp = New-AzPublicIpAddress -Name 'pip-sc500-0204-fw' -ResourceGroupName $Rg `
            -Location $Location -Sku Standard -AllocationMethod Static

$fw = New-AzFirewall -Name 'afw-sc500-0204' -ResourceGroupName $Rg -Location $Location `
          -VirtualNetworkName 'vnet-sc500-0204-hub' -PublicIpAddress $fwIp `
          -FirewallPolicyId $pol.Id -SkuTier 'Standard'

$fwPrivate = $fw.IpConfigurations[0].PrivateIPAddress
$fwPrivate
```

### 3.3 Force spoke egress through it

```powershell
$rt = New-AzRouteTable -Name 'rt-sc500-0204-spoke' -ResourceGroupName $Rg -Location $Location
Add-AzRouteConfig -Name 'default-to-fw' -AddressPrefix '0.0.0.0/0' `
                  -NextHopType VirtualAppliance -NextHopIpAddress $fwPrivate `
                  -RouteTable $rt | Set-AzRouteTable | Out-Null

$spoke = Get-AzVirtualNetwork -Name 'vnet-sc500-0204-spoke' -ResourceGroupName $Rg
Set-AzVirtualNetworkSubnetConfig -VirtualNetwork $spoke -Name 'snet-workload' `
    -AddressPrefix '10.41.1.0/24' -RouteTable $rt | Set-AzVirtualNetwork | Out-Null
```

### 3.4 Prove the rules, and then prove the trap

```powershell
function Test-Egress($url) {
    (Invoke-AzVMRunCommand -ResourceGroupName $Rg -VMName 'vm-sc500-0204' `
        -CommandId 'RunShellScript' `
        -ScriptString "curl -s -o /dev/null -m 10 -w '%{http_code}' $url").Value[0].Message
}

Test-Egress 'https://www.microsoft.com'      # allowed by the application rule
Test-Egress 'https://www.wikipedia.org'      # no rule matches -> denied
```

Now add the mistake on purpose:

```powershell
$badRule = New-AzFirewallPolicyNetworkRule -Name 'allow-all-443' `
               -SourceAddress '10.41.0.0/16' -DestinationAddress '*' `
               -DestinationPort 443 -Protocol TCP

$badRc = New-AzFirewallPolicyFilterRuleCollection -Name 'rc-net-broad' -Priority 100 `
             -Rule $badRule -ActionType 'Allow'

Set-AzFirewallPolicyRuleCollectionGroup -Name 'rcg-baseline' -Priority 200 `
    -RuleCollection $appRc,$netRc,$badRc -FirewallPolicyObject $pol

Start-Sleep 60
Test-Egress 'https://www.wikipedia.org'      # now allowed
```

**Your FQDN filtering just stopped existing.** A network rule matched first, so
application rules were never evaluated - and this happened despite the application rule
being perfectly correct and the network rule being in the same group. Type order beats
priority. Remove the broad rule and confirm the deny returns.

### 3.5 Read what it logged

Firewall diagnostic settings need a workspace, which arrives in 04-02. For now, use
**Firewall** → **Logs** in the portal and note the resource-specific tables you will
query later: `AZFWNetworkRule`, `AZFWApplicationRule`, `AZFWIdpsSignature`. The
application rule log records **the FQDN requested** - the closest thing Azure has to a
proxy log, and the reason this is worth ingesting in Domain 4.

## Part 4 - Network Watcher diagnostics

```powershell
$nw  = Get-AzNetworkWatcher -Location $Location
$nic = Get-AzNetworkInterface -ResourceGroupName $Rg | Where-Object Name -like '*0204*'

# 1. Effective security rules - NSGs, defaults, and any AVNM admin rules, in order
Get-AzEffectiveNetworkSecurityGroup -NetworkInterfaceName $nic.Name -ResourceGroupName $Rg |
    Select-Object -ExpandProperty EffectiveSecurityRules |
    Select-Object Name, Access, Direction, Priority | Format-Table -AutoSize

# 2. Next hop - proves the UDR is doing what you think
Get-AzNetworkWatcherNextHop -NetworkWatcher $nw -TargetVirtualMachineId $vm.Id `
    -SourceIPAddress $nic.IpConfigurations[0].PrivateIpAddress `
    -DestinationIPAddress '8.8.8.8'

# 3. IP flow verify - one five-tuple, one verdict, one rule name
Test-AzNetworkWatcherIPFlow -NetworkWatcher $nw -TargetVirtualMachineId $vm.Id `
    -Direction Outbound -Protocol TCP `
    -LocalIPAddress $nic.IpConfigurations[0].PrivateIpAddress -LocalPort 50000 `
    -RemoteIPAddress '8.8.8.8' -RemotePort 443
```

Next hop should return **VirtualAppliance** and the firewall's private address. If it
returns **Internet**, the route table is not associated with the subnet and every
firewall rule above is decorative.

Note what IP flow verify does *not* tell you: it evaluates NSGs and admin rules, not
firewall policy. A flow can be Allow here and still be denied at the firewall. Knowing
which tool answers which question is the exam skill.

## Part 5 - Microsoft Entra Private Access (licence-gated walkthrough)

**Check first:** Entra admin center → **Global Secure Access**. If the blade prompts
for licensing, your tenant does not have it and E5 alone will not provide it. Activate
a trial if one is offered; otherwise complete this as a walkthrough.

1. **Global Secure Access** → **Connect** → **Traffic forwarding**. Note the three
   profiles and that **Private access** is the one this objective needs.
2. **Connect** → **Connectors**. Read what the private network connector does: it is
   installed *inside* your network and dials **out**. Nothing inbound is published.
3. **Applications** → **Quick access**. Read the guidance that it is a **transition
   state** for replacing a VPN, not the destination.
4. **Applications** → **Enterprise applications** → **New application** → Global Secure
   Access app. This is per-app access: a named app, specific FQDNs or IPs, specific TCP
   and UDP ports.
5. **The step that matters:** open that application in **Enterprise applications** and
   assign a Conditional Access policy to it. A private TCP service behind a connector
   is now governed by MFA and device compliance, because Private Access publishes it as
   an enterprise application. Write down why a VPN gateway cannot do this.

Deliverable if you are licence-blocked: a one-page design for replacing a site-to-site
VPN with per-app access - connector placement, app definitions, the Conditional Access
policies you would attach, and what you would lose by using Quick Access instead.

```powershell
    Select-Object Name, @{n='RouteTable';e={$_.RouteTable.Id -ne $null}}

# 5. Nothing broad left in the policy

    -AzureFirewallPolicyName 'afwp-sc500-0204').Properties.RuleCollection.Name
```

### Portal validation

**Firewall** → **Logs**, and VM → **Networking** → **Effective security rules**. Between
them they answer both halves of "why was this blocked" - the firewall policy and the
NSG layer are different answers to the same question and the exam expects you to reach
for the right one.

## Teardown

**Mandatory, and urgent.** The firewall is the most expensive object in Domain 2.

### 1. Resources
- [ ] **Delete the Azure Firewall first**, before anything else:
      ```powershell
      Remove-AzFirewall -Name 'afw-sc500-0204' -ResourceGroupName $Rg -Force
      ```
- [ ] Delete the firewall's public IP - it bills separately and survives:
      ```powershell
      Remove-AzPublicIpAddress -Name 'pip-sc500-0204-fw' -ResourceGroupName $Rg -Force
      ```
- [ ] Stop and delete the VM, then the private endpoint, DNS zone, storage account,
      route table, peerings, and virtual networks:
      ```powershell
      Remove-AzResourceGroup -Name rg-sc500-lab-02-04 -Force
      ```
- [ ] The firewall **policy** costs nothing and can be kept if you want to redeploy
      later - but delete it with the group unless you have a reason

- [ ] No Defender plan was enabled by this lab - confirm none is at Standard anyway
- [ ] Remove any route table still associated with a subnet elsewhere

### 3. Directory scope
- [ ] If you enabled a Global Secure Access trial in Part 5, decide deliberately
      whether to leave the traffic forwarding profile on. A connector left registered is
      a standing inbound-capable path into your private network.
- [ ] Remove any Conditional Access policy created for a Private Access app

- [ ] None. Private DNS zones and firewalls delete outright.

### 5. Access

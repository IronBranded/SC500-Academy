# Lab 03-04 - Server and Virtual Machine Security

**Objective:** Implement security for servers and virtual machines (VMs)
**Estimated cost:** **HIGH.** Three independent hourly meters run at once: the VM while
allocated, **Azure Bastion per host**, and **Defender for Servers Plan 2 per server**. The
Defender plan is subscription-scoped and survives resource group deletion.
**Licensing required:** Azure subscription; Defender for Servers Plan 2 for Parts 4-6.
**Time:** ~180 minutes, one sitting.

> Complete **Module 0** before running this lab. Activate your roles through PIM.
>
> **Start a timer when Bastion finishes deploying.** Same discipline as Azure Firewall in
> 02-04 and API Management in 03-03.
>
> **Linux, deliberately.** Ubuntu Gen2 supports trusted launch, Defender for Endpoint,
> file integrity monitoring, and machine configuration, and carries no Windows licensing
> cost. Nothing in this objective requires Windows.

## Prerequisites

- PIM activation: **Contributor** and **User Access Administrator** at subscription scope,
  or Owner.
- Modules: `Az.Compute`, `Az.Network`, `Az.Security`, `Az.Resources`,
  `Az.ConnectedMachine` for Part 7.

```powershell
$Location = 'canadacentral'
$LabId    = '03-04'
$Rg       = "rg-sc500-lab-$LabId"
$Vm       = 'vm-sc500-0304'
$SubId    = (Get-AzContext).Subscription.Id

New-AzResourceGroup -Name $Rg -Location $Location -Tag @{ 'sc500-module' = $LabId } -Force
```

## Part 1 - Build the VM correctly the first time

### 1.1 Network first, with no public IP

```powershell
$subnetVm  = New-AzVirtualNetworkSubnetConfig -Name 'snet-workload' -AddressPrefix '10.50.1.0/24'
# Bastion requires this exact subnet name and a /26 or larger
$subnetBas = New-AzVirtualNetworkSubnetConfig -Name 'AzureBastionSubnet' -AddressPrefix '10.50.0.0/26'

$vnet = New-AzVirtualNetwork -Name 'vnet-sc500-0304' -ResourceGroupName $Rg `
                             -Location $Location -AddressPrefix '10.50.0.0/16' `
                             -Subnet $subnetVm,$subnetBas -Tag @{ 'sc500-module' = $LabId }
```

### 1.2 Trusted launch, no public IP, no open ports

```powershell
$cred = Get-Credential -Message 'Local admin for the lab VM (not stored anywhere)'

$vmConfig = New-AzVMConfig -VMName $Vm -VMSize 'Standard_B2s' `
                -SecurityType 'TrustedLaunch' -EnableSecureBoot $true -EnableVtpm $true |
    Set-AzVMOperatingSystem -Linux -ComputerName $Vm -Credential $cred |
    Set-AzVMSourceImage -PublisherName 'Canonical' `
                        -Offer 'ubuntu-24_04-lts' -Skus 'server' -Version 'latest'

$nic = New-AzNetworkInterface -Name "nic-$Vm" -ResourceGroupName $Rg -Location $Location `
           -SubnetId ($vnet.Subnets | Where-Object Name -eq 'snet-workload').Id
$vmConfig = Add-AzVMNetworkInterface -VM $vmConfig -Id $nic.Id

New-AzVM -ResourceGroupName $Rg -Location $Location -VM $vmConfig `
         -Tag @{ 'sc500-module' = $LabId }
```

Confirm what you built:

```powershell
$vm = Get-AzVM -ResourceGroupName $Rg -Name $Vm
$vm.SecurityProfile | Format-List SecurityType
$vm.SecurityProfile.UefiSettings | Format-List SecureBootEnabled, VTpmEnabled
(Get-AzNetworkInterface -ResourceGroupName $Rg).IpConfigurations.PublicIpAddress   # expect empty
```

> **Trusted launch is now the default for new Gen2 VMs.** This lab sets it explicitly so
> you see the properties. In an exam scenario, the question is more likely to be "confirm
> it is on" than "turn it on."

### 1.3 Encryption at host

```powershell
# Requires deallocation - this is the constraint the exam asks about
Stop-AzVM -ResourceGroupName $Rg -Name $Vm -Force

$vm = Get-AzVM -ResourceGroupName $Rg -Name $Vm
$vm.SecurityProfile.EncryptionAtHost = $true
Update-AzVM -ResourceGroupName $Rg -VM $vm

Start-AzVM -ResourceGroupName $Rg -Name $Vm
(Get-AzVM -ResourceGroupName $Rg -Name $Vm).SecurityProfile.EncryptionAtHost
```

If it fails, your subscription may not have the feature registered, or the VM size may not
support it. Both are real-world blockers worth meeting once.

Record the difference from server-side encryption, which was already on and which you
never configured: **encryption at host also covers the temp disk and host cache.**

## Part 2 - Azure Bastion

> **Cost clock starts here.** Use the lowest SKU available to you. Check whether a
> Developer-tier deployment is offered in your region before deploying a dedicated host.

### Method A - Portal

1. **Bastions** → **Create**. Resource group `rg-sc500-lab-03-04`, virtual network
   `vnet-sc500-0304`. The `AzureBastionSubnet` you created is detected automatically.
2. Choose the lowest tier that meets your needs. Note what the higher tiers add - native
   client support, session recording, private-only deployment - and that each step up
   raises the hourly rate.
3. Create. Note the time when deployment completes.
4. VM → **Connect** → **Bastion** → sign in with the credential from Part 1.

You now have an interactive session to a VM with **no public IP and no inbound management
rule**. Confirm the negative as well as the positive:

```powershell
Get-AzNetworkSecurityGroup -ResourceGroupName $Rg |
    Select-Object -ExpandProperty SecurityRules |
    Select-Object Name, Direction, Access, DestinationPortRange
```

## Part 3 - Defender for Servers, and what it turns on by itself

### Method A - Portal

1. **Defender for Cloud** → **Environment settings** → subscription → **Defender plans**.
2. Set **Servers** to **On**, and select **Plan 2**. Save.
3. Open the plan's **Settings** under monitoring coverage and record the state of each
   component **before changing anything**:

   | Component | Expected state |
   | --- | --- |
   | Endpoint protection (Defender for Endpoint provisioning) | **On** |
   | Vulnerability assessment | **On** |
   | Agentless scanning for machines | **On** |
   | File integrity monitoring | **Off** |

   That table is the exam content. Three of four are on by default; the fourth is not, and
   it is the one people assume.

### Method B - PowerShell

```powershell
Get-AzSecurityPricing -Name 'VirtualMachines' | Format-List Name, PricingTier, SubPlan

Set-AzSecurityPricing -Name 'VirtualMachines' -PricingTier 'Standard' -SubPlan 'P2'

Get-AzSecurityPricing -Name 'VirtualMachines' | Format-List Name, PricingTier, SubPlan
```

### 3.3 Confirm EDR arrived

Wait for the Defender for Endpoint extension to be provisioned automatically, then:

```powershell
Get-AzVMExtension -ResourceGroupName $Rg -VMName $Vm |
    Select-Object Name, Publisher, ProvisioningState
```

You installed nothing. Automatic provisioning did it because the plan is on. **That is
what Plan 1 buys you** - Plan 2 adds everything below.

## Part 4 - Just-in-time VM access

### Method A - Portal

1. **Defender for Cloud** → **Workload protections** → **Just-in-time VM access**.
2. Find `vm-sc500-0304` under **Not configured**, select it, **Enable JIT on 1 VM**.
3. Review the default port list. Set SSH (22) to a maximum request time of **1 hour** and
   allowed source IPs **Per request**. Save.
4. Now request access: select the VM → **Request access** → port 22, your IP, 1 hour.
5. Immediately inspect the NSG:

```powershell
Get-AzNetworkSecurityGroup -ResourceGroupName $Rg |
    Select-Object -ExpandProperty SecurityRules |
    Select-Object Name, Priority, Direction, Access, SourceAddressPrefix, DestinationPortRange
```

A new allow rule exists, scoped to your address, and it will be removed automatically when
the window expires. Wait it out, or re-check later, and confirm it disappears.

6. **Defender for Cloud → Activity/audit**: the request is recorded - who, when, from
   where, for how long. In a tenant with standing open ports, none of that record exists.

> JIT is a **Plan 2** feature. If the option is greyed out, check your sub-plan.

## Part 5 - Agentless scanning and vulnerability assessment

1. **Defender for Cloud** → **Recommendations**, filtered to your VM. Vulnerability
   findings appear from **Microsoft Defender Vulnerability Management**, which was enabled
   by default alongside the Defender for Endpoint extension.
2. **Inventory** → your VM → review software inventory. This came from **agentless
   scanning**, which snapshotted the disk through cloud APIs. Nothing was installed for it
   and the VM's performance was unaffected.
3. Place a fake credential on the VM through Bastion - for example a file containing a
   plausible-looking connection string - and wait for the next agentless scan. Secrets
   scanning is the same engine you met in 01-02, pointed at a disk instead of a repository.
4. Write down the trade-off in one line each: what agentless gives you that the agent does
   not, and what the agent gives you that agentless cannot.

## Part 6 - File integrity monitoring and machine configuration

### 6a. Turn FIM on - it is not on

1. **Defender for Cloud** → **Environment settings** → subscription → **Servers** plan →
   **Settings** → **File integrity monitoring** → **On**.
2. Select a Log Analytics workspace. If you do not have one yet, create a lab-scoped one as
   in 02-02 and remember the **14-day soft delete** in teardown.
3. Configure monitored paths. On Linux, add `/etc/` and `/usr/bin/`.
4. Through Bastion, change a monitored file:

   ```bash
   sudo touch /etc/sc500-fim-test && sudo sh -c 'echo test >> /etc/sc500-fim-test'
   ```

5. **Change events from agentless collection stream on a 24-hour cadence**, so do not
   expect this immediately. Note what FIM records when it arrives: the file, the source of
   the change, the **account**, and the **initiating process**. That last pair is what
   makes it evidence rather than a notification.

> FIM now runs on **Defender for Endpoint**. Any guide that installs the Log Analytics
> agent or the Azure Monitor agent for FIM is describing the retired path.

### 6b. Azure Machine Configuration

```powershell
# The extension needs a system-assigned managed identity on the VM
Update-AzVM -ResourceGroupName $Rg -VM (Get-AzVM -ResourceGroupName $Rg -Name $Vm) `
            -IdentityType SystemAssigned

Set-AzVMExtension -ResourceGroupName $Rg -VMName $Vm `
                  -Name 'AzurePolicyforLinux' `
                  -Publisher 'Microsoft.GuestConfiguration' `
                  -ExtensionType 'ConfigurationforLinux' `
                  -TypeHandlerVersion '1.0' -Location $Location
```

Then assign a built-in machine configuration policy in **audit** mode - for example one of
the Linux security baseline definitions - scoped to the resource group, using the same
`New-AzPolicyAssignment` pattern from
[01-03](../01-identity-access-governance/01-03-lab.md).

Two things to confirm:

- **OS configuration assessment** in Defender for Cloud now produces results. It depends on
  this extension; without it the assessment is silent rather than clean.
- The distinction between **audit** and **enforce** is the same one as `Audit` versus
  `DeployIfNotExists` in 01-03, reaching inside the guest.

## Part 7 - Azure Arc (walkthrough, or optional real onboarding)

Arc is free to register and governs machines you already own, so this part costs nothing -
but it needs a machine outside Azure.

**If you have a spare local VM or laptop you are willing to enrol:**

1. **Azure Arc** → **Machines** → **Add** → **Generate script**. Read what the script does
   before running it: it installs the Connected Machine agent and registers the machine as
   an ARM resource.
2. Run it. The machine appears in Azure with a resource ID.
3. Now apply the Azure controls to it: assign the same machine configuration policy from
   6b, and confirm the machine is in scope of the Defender for Servers plan.

**If not, answer on paper:**

1. What exactly does Arc *give* the machine? (Answer in terms of an ARM resource ID and
   what that unlocks.)
2. Your organisation has 40 servers in AWS. What is the onboarding path, and why is it not
   40 individual agent installations?
3. An Arc machine appears in Defender for Cloud with no recommendations. List three
   possible causes in the order you would check them.

```powershell
$vm = Get-AzVM -ResourceGroupName $Rg -Name $Vm
$vm.SecurityProfile | Format-List SecurityType, EncryptionAtHost
$vm.SecurityProfile.UefiSettings | Format-List SecureBootEnabled, VTpmEnabled

# 3. Defender plan and sub-plan

# 4. Extensions present: Defender for Endpoint (auto), machine configuration (you)
Get-AzVMExtension -ResourceGroupName $Rg -VMName $Vm | Select-Object Name, Publisher

Get-AzNetworkSecurityGroup -ResourceGroupName $Rg |
    Select-Object -ExpandProperty SecurityRules |
    Where-Object DestinationPortRange -eq 22
```

### Portal validation

**Defender for Cloud → Just-in-time VM access** showing the VM as configured, and the VM's
**Recommendations** list populated by MDVM and OS configuration assessment. Those two are
the surfaces an exam question means by "how would you confirm the machine is protected."

## Teardown

**Mandatory and urgent.** Three hourly meters, and one of them is subscription-scoped.

### 1. Resources
- [ ] **Delete Bastion first** - it is the largest hourly charge:
      ```powershell
      Remove-AzBastion -ResourceGroupName $Rg -Name '<bastion-name>' -Force
      ```
- [ ] Delete its public IP if one was created separately
- [ ] Stop and delete the VM, disks, NIC, NSG, and virtual network:
      ```powershell
      Remove-AzResourceGroup -Name rg-sc500-lab-03-04 -Force
      ```
- [ ] Delete the lab Log Analytics workspace if you created one for FIM

### 2. Subscription scope
- [ ] **Set the Servers plan back to Free - this is the one that keeps billing:**
      ```powershell
      Set-AzSecurityPricing -Name 'VirtualMachines' -PricingTier 'Free'
      Get-AzSecurityPricing | Where-Object PricingTier -eq 'Standard'   # expect empty
      ```
- [ ] Remove the JIT policy for the deleted VM if it persists in Defender for Cloud
- [ ] Remove the machine configuration policy assignment from 6b
- [ ] Check for orphaned role assignments left by the VM's system-assigned identity

### 3. Directory scope
- [ ] The VM's system-assigned identity is deleted with the VM. Confirm no orphaned service
      principal remains
- [ ] **If you onboarded a machine to Arc:** unregister it properly -
      `azcmagent disconnect` on the machine, then delete the Azure resource. An Arc machine
      left registered is a standing agent with an Azure identity on a computer you may
      later repurpose

### 4. Soft-deleted remains
- [ ] **A Log Analytics workspace created for FIM is soft-deleted for 14 days** and
      recreating the same name in the same resource group and region recovers it - the trap
      from 00-03 and 02-02
- [ ] Managed disks are deleted with the VM only if the delete-with-VM option was set;
      verify no orphaned disks remain:
      ```powershell
      Get-AzDisk | Where-Object Name -like '*sc500*'
      ```

### 5. Access
- [ ] Deactivate every PIM role activated for this lab
- [ ] Discard the local VM credential from Part 1

### 6. Verify
- [ ] `Get-AzBastion` returns nothing **anywhere in the subscription**
- [ ] `Get-AzVM -Status | Where-Object PowerState -eq 'VM running'` returns nothing
- [ ] `Get-AzDisk | Where-Object Name -like '*sc500*'` returns nothing
- [ ] `Get-AzSecurityPricing | Where-Object PricingTier -eq 'Standard'` is empty
- [ ] **Check Cost Management tomorrow.** Bastion and the Servers plan both lag

```powershell
.\scripts\teardown\Remove-LabResourceGroup.ps1 -LabId '03-04' -WhatIf
```

> The sweep catches running VMs and Defender plans at Standard. It does **not** catch
> Bastion hosts, orphaned managed disks, soft-deleted workspaces, or Arc registrations.
> Buckets 1, 3 and 4 above exist because of those gaps.

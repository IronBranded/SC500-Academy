# Lab 04-01 - Security Posture with Defender for Cloud

**Objective:** Manage security posture by using Defender for Cloud
**Estimated cost:** **Medium, with one sharp edge.** Defender CSPM bills per billable
resource, so a near-empty lab subscription is cheap. **Defender EASM bills per asset in
inventory, and a discovery against a real domain can return thousands of assets.** Part 6 is
walkthrough-first for that reason.
**Licensing required:** Azure subscription. Defender CSPM for Parts 1-4; Defender EASM is a
separate resource and a separate bill.
**Time:** ~150 minutes across **two sessions** - attack paths and the security graph need time
to populate.

> Complete **Module 0** before running this lab. Activate your roles through PIM.
>
> **Enable Defender CSPM as the Subscription Owner.** If you enable it with anything less,
> the agentless scanner will not start, and Parts 2 and 3 will produce empty results that
> look like a clean environment. This is the single most important instruction in the lab.
>
> **This lab needs something to find.** It works best if you still have a resource group from
> 03-04 or 03-05. If not, Part 0 builds a deliberately flawed one.

## Prerequisites

- PIM activation: **Owner** at subscription scope. Not Contributor, for the reason above.
- Modules: `Az.Security`, `Az.Resources`, `Az.Compute`, `Az.Storage`.

```powershell
$LabId    = '04-01'
$Rg       = "rg-sc500-lab-$LabId"
$Location = 'canadacentral'
$SubId    = (Get-AzContext).Subscription.Id

New-AzResourceGroup -Name $Rg -Location $Location -Tag @{ 'sc500-module' = $LabId } -Force
```

## Part 0 - Build something worth finding

Attack path analysis needs a chain. Build one deliberately: an internet-exposed VM, with a
managed identity, with more permission than it needs.

```powershell
$cred = Get-Credential -Message 'Local admin for the lab VM (not stored anywhere)'

$vm = New-AzVM -ResourceGroupName $Rg -Location $Location -Name 'vm-sc500-0401' `
               -Size 'Standard_B2s' -Image 'Ubuntu2204' -Credential $cred `
               -OpenPorts 22 `                               # deliberately exposed
               -SystemAssignedIdentity `
               -Tag @{ 'sc500-module' = $LabId }

$sa = New-AzStorageAccount -ResourceGroupName $Rg -Name "stsc500$((Get-Random -Maximum 99999))" `
          -Location $Location -SkuName Standard_LRS -Kind StorageV2 `
          -Tag @{ 'sc500-module' = $LabId }

# More permission than any VM needs - this is the third link in the chain
New-AzRoleAssignment -ObjectId $vm.Identity.PrincipalId `
                     -RoleDefinitionName 'Contributor' `
                     -Scope "/subscriptions/$SubId/resourceGroups/$Rg"
```

You have just built the scenario from the module text: an internet-facing resource, with
vulnerabilities it will accumulate on its own, holding an identity with real reach. Three
separate findings. One attack path.

> Delete this the same day. An SSH port open to the internet is the most exploited
> misconfiguration there is, and this one is real.

---

## Part 1 - The two plans

### 1.1 Look at free first

Before enabling anything, record what Foundational CSPM gives you:

1. **Defender for Cloud → Overview**: secure score, active recommendations, asset inventory.
2. **Recommendations**: continuous assessment against the **Microsoft cloud security
   benchmark**.
3. **Regulatory compliance**: MCSB only.
4. Try **Cloud security explorer** and **Attack path analysis**. Both are unavailable or empty.

> **Changing default:** from **27 October 2026** Foundational CSPM becomes **opt-in** for new
> Azure subscriptions rather than on by default. Check whether your subscription has it before
> assuming a clean baseline.

### 1.2 Enable Defender CSPM - as Owner

```powershell
# Confirm you are Owner at subscription scope FIRST
Get-AzRoleAssignment -SignInName (Get-AzContext).Account.Id -Scope "/subscriptions/$SubId" |
    Where-Object Scope -eq "/subscriptions/$SubId" | Select-Object RoleDefinitionName

Set-AzSecurityPricing -Name 'CloudPosture' -PricingTier 'Standard'
Get-AzSecurityPricing -Name 'CloudPosture' | Format-List Name, PricingTier
```

Then confirm the thing that actually matters:

**Defender for Cloud → Environment settings → subscription → Defender CSPM → Settings** →
**Agentless scanning for machines** must be **On**. If it is off and greyed, the plan was
enabled by someone without Owner - that is the cause, and re-enabling as Owner is the fix.

## Part 2 - Attack paths

Wait for the graph to build. This is the point at which to stop for the day; results typically
need hours, not minutes.

**Session 2:**

1. **Defender for Cloud → Attack path analysis**.
2. Find the path involving `vm-sc500-0401`. Read it as a chain rather than a list: internet
   exposure → vulnerability → identity → permission → target.
3. Compare it against the **Recommendations** view filtered to the same VM. The recommendations
   are all present and individually unremarkable. The path is one item and it is urgent.

**Write the difference down in your own words.** This is the conceptual centre of Domain 4, and
an exam question asking you to "prioritise" is asking for this.

4. Remediate one link - remove the Contributor assignment - and watch the path change or
   disappear. Which single link you break is a real decision, and cheapest-to-break is not
   always the same as most-effective.

---

## Part 3 - Cloud security explorer

This is the hunting surface, and it is worth treating as such.

Run these, in order:

1. Internet-exposed VMs
2. Internet-exposed VMs **with a high-severity vulnerability**
3. Internet-exposed VMs with a high-severity vulnerability **that have a managed identity**
4. …**with permissions on a storage account**

Each clause narrows a population. By the fourth you have the same result as attack path
analysis, reached by asking rather than by reading - which is the difference between a report
and a hunt.

Then note where every piece of data came from: agentless machine scanning (03-04), MDVM
(03-04), container findings if you still have a cluster (03-05), secrets scanning (01-02),
storage configuration (02-01). **The graph is the sum of the plans you enabled.** A subscription
with fewer plans has a thinner graph and fewer attack paths - not fewer attack paths in reality.

## Part 4 - Standards, plans, and governance

### 4.1 Add a standard

**Environment settings → subscription → Security policies → Add more standards.** Assign one
framework. Return to **Regulatory compliance** and trace one control down to the
recommendations that evidence it, and from there to the Azure Policy definition underneath -
the chain from 01-03, seen from the top.

### 4.2 Enable workload plans by policy, not by hand

```powershell
Get-AzSecurityPricing | Select-Object Name, PricingTier | Sort-Object Name
```

Rather than switching each on individually, find the built-in Azure Policy definitions that
configure Defender plans and assign one at **subscription** scope using the pattern from
[01-03](../01-identity-access-governance/01-03-lab.md). Confirm the policy turns the plan on.

**That is the answer to "the plan must apply to subscriptions created next year."** Manual
enablement covers the subscriptions that exist today.

> Keep this brief and turn the plans back off in teardown. Every one of them bills.

### 4.3 Governance rules

**Environment settings → Governance rules** → create a rule assigning an owner and a due date
to a recommendation set. Findings without an owner do not get fixed, and this is the mechanism
the exam means when it asks how you would drive remediation rather than report it.

## Part 5 - Multicloud (walkthrough)

Connecting a real AWS or GCP account requires credentials in that cloud, which is outside this
guide's lab environment. Walk the configuration surface:

1. **Environment settings → Add environment → Amazon Web Services**. Read through the
   connector: account or organisation scope, the access it establishes, which plans you can
   enable on it, and the **Azure Arc auto-provisioning** option for discovered instances.
2. Cancel. Then answer, on paper:
   - What does the connector give you that an AWS-native tool does not? (Answer in terms of one
     inventory, one secure score, and **cross-cloud attack paths**.)
   - If you decline Arc auto-provisioning, which capabilities do you lose for those EC2
     instances?
   - Your organisation has 40 EC2 instances. Compare connector-based onboarding against
     installing the Arc agent on each.

## Part 6 - Defender EASM

> **Cost warning, read before clicking.** EASM is billed **per asset in inventory**. Seeding a
> discovery with a real organisation's primary domain routinely returns thousands of assets,
> all of them billable. Do not point this at your employer's domain out of curiosity.

**Walkthrough, which is the right default:**

1. **Create a resource → Microsoft Defender EASM**. Read the create blade and note it is its
   own Azure resource with its own billing, separate from Defender for Cloud.
2. Read the discovery configuration: **seeds** are domains, IP blocks, hosts, email contacts,
   ASNs, and WHOIS organisations, and discovery runs **recursively** from them.
3. Note the inventory states - approved, candidate, requires investigation, dismissed - and
   that triage is the actual work.

**Optional real run, tightly scoped:** if you own a personal domain with a handful of records,
use *that* as the single seed. Expect a small inventory, look at what it found that you had
forgotten, and **delete the EASM resource the same day**.

Then answer the question the objective is really asking: your internal inventory is complete
and your CSPM secure score is 90%. What class of asset does EASM find that neither of those
can, and why?

## Validation

```powershell
# 1. Both CSPM plans, and the agentless scanner state
Get-AzSecurityPricing | Where-Object Name -in 'CloudPosture','VirtualMachines' |
    Select-Object Name, PricingTier, SubPlan

# 2. Workload plans currently billing
Get-AzSecurityPricing | Where-Object PricingTier -eq 'Standard' | Select-Object Name

# 3. The deliberately flawed resources still exist for the graph to find
Get-AzRoleAssignment -Scope "/subscriptions/$SubId/resourceGroups/$Rg" |
    Select-Object DisplayName, RoleDefinitionName
```

In the portal:

- **Attack path analysis** shows at least one path through `vm-sc500-0401`
- **Cloud security explorer** returns results for the four-clause query in Part 3
- **Regulatory compliance** shows MCSB plus the standard you assigned
- **Governance rules** shows a rule with an owner and a due date

## Teardown

**Mandatory.** The exposed VM is a live risk, and three plan types are billing.

### 1. Resources
- [ ] **Delete the resource group today** - the SSH port from Part 0 is open to the internet:
      ```powershell
      Remove-AzResourceGroup -Name rg-sc500-lab-04-01 -Force
      ```
- [ ] **If you created an EASM resource, delete it now** - it bills per asset in inventory and
      the inventory does not shrink on its own

### 2. Subscription scope
- [ ] **Turn Defender CSPM back to Free:**
      ```powershell
      Set-AzSecurityPricing -Name 'CloudPosture' -PricingTier 'Free'
      ```
- [ ] Turn off every workload plan the Part 4.2 policy enabled - **the policy will re-enable
      them if you leave the assignment in place, so remove the assignment first:**
      ```powershell
      Get-AzPolicyAssignment -Scope "/subscriptions/$SubId" |
          Where-Object Name -like 'sc500-0401*' |
          ForEach-Object { Remove-AzPolicyAssignment -Id $_.Id }

      Get-AzSecurityPricing | Where-Object PricingTier -eq 'Standard' |
          ForEach-Object { Set-AzSecurityPricing -Name $_.Name -PricingTier 'Free' }
      ```
- [ ] Remove the compliance standard assigned in Part 4.1
- [ ] Remove the governance rule from Part 4.3
- [ ] Remove the orphaned Contributor assignment left by the VM's deleted identity

### 3. Directory scope
- [ ] Confirm no orphaned service principal remains from the VM's system-assigned identity

### 4. Soft-deleted remains
- [ ] None from this lab, unless you created an EASM workspace - confirm it is gone rather than
      stopped

### 5. Access
- [ ] Deactivate the **Owner** activation. This lab required the highest privilege in the guide
      and it should not outlive the session
- [ ] Discard the local VM credential

### 6. Verify
- [ ] `Get-AzSecurityPricing | Where-Object PricingTier -eq 'Standard'` is **empty**
- [ ] `Get-AzPolicyAssignment -Scope "/subscriptions/$SubId" | Where-Object Name -like 'sc500-*'`
      returns nothing
- [ ] `Get-AzResource | Where-Object ResourceType -like '*Easm*'` returns nothing
- [ ] `Get-AzVM -Status | Where-Object PowerState -eq 'VM running'` returns nothing
- [ ] **Check Cost Management tomorrow**, with particular attention to any EASM line

```powershell
.\scripts\teardown\Remove-LabResourceGroup.ps1 -LabId '04-01' -WhatIf
```

> This is the one lab where the teardown order genuinely matters beyond cost: **remove the
> policy assignment before turning the plans off**, or the policy will turn them back on and
> you will find them still billing next week.

Managed identity vs service principal1.1.41.1.6

An application needs to call an Azure service. Which identity should it use?

“no credentials to store or rotate, app runs on an Azure VM / App Service”→Managed identity“GitHub Actions or an on-premises job must authenticate without a secret”→Workload identity federation, on an app registration or a user-assigned managed identity“one identity shared by several resources”→User-assigned managed identity

Trap. Treating a managed identity as automatically least-privilege. It removes the credential problem, not the permission problem.

PIM vs Conditional Access1.1.11.1.2

Is the requirement about how long someone holds privilege, or about the conditions of a sign-in?

“just-in-time, eligible, time-bound, approval to activate”→PIM“compliant device, location, sign-in risk, block legacy authentication”→Conditional Access

Trap. Answering "require MFA for admins" with PIM alone, or "remove permanent admins" with Conditional Access.

Azure RBAC vs Azure Policy1.3.11.3.51.3.7

Is the requirement about who can act, or about what any resource is allowed to look like?

“only the network team may manage virtual networks”→Azure RBAC“no storage account may allow public blob access, even for Owners”→Azure Policy (Deny)“add a tag automatically / deploy diagnostic settings when missing”→Azure Policy (Modify / DeployIfNotExists)

Trap. Picking a custom role to stop people creating resources in the wrong region - that is a policy (allowed locations).

Preventive vs detective controls1.3.11.3.34.1.14.1.3

Must the bad thing be stopped, or seen and acted on?

“must not be able to create”→Preventive (Azure Policy Deny)“notify the SOC when it happens”→Detective (alert / analytics rule)

Trap. Answering a "prevent" requirement with Audit, or with a Defender alert.

Secrets vs keys vs certificates in Key Vault1.2.5

What kind of sensitive material is it, and does the application ever need to see it?

“connection string, API key, password”→Secret“customer-managed key, encryption at rest, the key must never leave an HSM”→Key“TLS certificate with automatic renewal”→Certificate

Trap. Storing an encryption key as a secret so the app can "use it" - the point of a key is that it never leaves the vault.

Key Vault: Azure RBAC vs access policies1.2.3

How should data-plane access to a vault be granted?

“grant an app read access to one specific secret only”→Azure RBAC scoped to the secret“make vault access PIM-eligible and reviewable”→Azure RBAC

Trap. Assuming Key Vault Contributor cannot read secrets - under access policies it can grant itself access.

Private endpoint vs service endpoint2.1.22.3.6

Must the service have a private IP address in your network, or is it enough to limit its public endpoint to your subnets?

“private IP, reachable from on-premises, disable public access”→Private endpoint“allow only these subnets through the storage firewall, no extra cost”→Service endpoint

Trap. Assuming a private endpoint closes public access - you must also disable public network access, and get DNS right.

NSG vs Azure Firewall vs security admin rule2.3.12.3.22.3.8

Where should this traffic rule live - next to the workload, centrally for inspection, or as an organisation-wide floor?

“allow web tier to reach database tier on 1433 only”→NSG with application security groups“allow outbound only to *.contoso.com, block known malicious IPs”→Azure Firewall“block RDP from the internet in every virtual network, even if a team adds an allow”→Security admin rule

Trap. Choosing an NSG to filter outbound traffic by domain name - NSGs cannot; Azure Firewall application rules can.

Restricted Content Discovery vs Restricted Access Control3.1.1

Should overshared content stop appearing in Copilot and search, or should people lose access to it?

“stop it appearing in Copilot without disrupting the team”→RCD“only the legal group may open the site”→RAC

Trap. Choosing RCD when the requirement is that unauthorised users must not be able to open the files.

On-behalf-of agent vs autonomous agent3.1.43.1.6

Whose token does the agent use - a signed-in user's, or its own?

“assistant that acts for the signed-in user”→On-behalf-of - governed by user policies“nightly agent with no user present”→Autonomous - agent identity policies

Trap. Assuming your All users MFA policy covers agents - it does not include agent identities or agents' user accounts.

AI gateway vs Foundry guardrails vs Defender for AI Services3.1.73.1.83.1.93.1.10

Is the requirement about AI traffic, AI content, or detecting attacks?

“one app must not exhaust the token quota”→AI gateway (llm-token-limit)“scan what a tool returns before the agent uses it”→Foundry guardrail on tool response“SOC must be alerted to jailbreak attempts”→Defender for AI Services

Trap. Expecting Defender for AI Services to block a prompt - it alerts. Blocking is guardrails, the gateway, or Defender real-time protection for agents (preview).

Web Application Firewall vs API Management3.3.83.3.9

Is the requirement to block malicious requests, or to control which callers may use an API and how much?

“block SQL injection and XSS”→WAF managed rules (Prevention mode)“callers must present a valid Entra token, each limited independently”→API Management (validate-jwt, rate limits)

Trap. Using a WAF to enforce per-consumer quotas or token validation - that is API Management.

Azure Bastion vs just-in-time VM access3.2.23.2.3

Is the requirement to remove the public path to the VM, or to keep management ports closed until needed?

“RDP without a public IP, record sessions”→Azure Bastion (Premium for recording)“open port 3389 for one hour from one IP on request”→Just-in-time VM access

Trap. Picking Bastion for "ports open only when needed", or JIT for "no public IP".

Agentless scanning vs the Defender for Endpoint agent3.2.63.2.74.1.5

Do you need findings without installing anything, or real-time detection and response on the machine?

“vulnerability findings without installing anything”→Agentless scanning“detect and respond to attacker behaviour on the server”→Defender for Endpoint (EDR)

Trap. Treating agentless scanning as a replacement for EDR.

Posture management vs workload protection4.1.14.1.3

Is the requirement about how exposed things are, or about attacks happening now?

“prioritise findings, attack path, internet-exposed VM with a critical CVE”→Defender CSPM“alert on suspicious access to a storage account / SQL injection attempt”→Workload protection plan

Trap. Expecting Defender CSPM to raise an alert for malware on a storage account - that is Defender for Storage.

Security Copilot roles vs underlying service roles4.3.24.3.3

Does this role let someone use Security Copilot, or see the data Copilot reasons over?

“analyst can query Purview but not Sentinel through Copilot”→Missing Sentinel service role“restrict who can open Security Copilot”→Copilot contributor assignment

Trap. Restricting Copilot contributor and believing that limits data exposure - data access was always the service roles.

Sentinel analytics tier vs data lake tier4.2.74.2.9

Will this data drive detections and hunting, or is it kept for history and compliance?

“must be usable by analytics rules”→Analytics tier“keep seven years for compliance at low cost”→Data lake tier (total retention)

Trap. Moving a table that feeds analytics rules to the data lake - the rules stop working.

Sentinel automation rule vs playbook4.2.8

Is the requirement to route and manage incidents, or to take action in other systems?

“automatically assign and tag new incidents”→Automation rule“create a ServiceNow ticket / disable the user in Entra”→Playbook (run by an automation rule)

Trap. Granting Playbook Operator to someone who must build playbooks - building needs Logic Apps permissions.

Windows Security Events via AMA vs Windows Forwarded Events4.2.6

Should each server send its own Security log, or should endpoints forward to a collector?

“collect only these event IDs from each server”→Windows Security Events via AMA with custom XPath“endpoints must not connect to Azure directly”→Windows Forwarded Events via a collector

Trap. Forwarding events with WEF and assuming the built-in SecurityEvent rules now cover them.

How to read a scenario

  1. Find the verb. Prevent, block, must not wants a preventive control. Detect, alert, notify wants Defender or Sentinel. Prove, report wants compliance or audit.
  2. Find the subject. A person, a workload, an agent, a network path or the data? That names the layer.
  3. Find the constraint that kills options. Without a credential. No public IP. No team can override. Without disrupting users. Without installing anything.
  4. Find the scope. Every subscription, including future ones means policy at a management group. One secret only means the narrowest role at the narrowest scope.
  5. Strike the answers that solve a different layer, then the ones that detect when the question says prevent.

Domain 1 Identity, access, governance

  • “the same identity must survive a VM rebuild”
    User-assigned managed identity    1.1.6
  • “no credential in code or configuration, runs on Azure”
    Managed identity    1.1.6
  • “runs in GitHub Actions, no secret allowed”
    Workload identity federation: app registration or user-assigned MI    1.1.4
  • “three policies apply; one of them blocks”
    Blocked. Block beats every grant    1.1.2
  • “passkey or certificate; SMS must not count”
    Authentication strength, not plain MFA    1.1.3
  • “delegated vs application permission”
    Delegated = the user’s reach. Application = tenant-wide, admin consent    1.1.5
  • “nobody holds the role until they need it; approval; four hours”
    PIM eligible assignment + role settings    1.1.1
  • “Contributor must not grant themselves secret access”
    Key Vault Azure RBAC permission model    1.2.3
  • “read one specific secret and nothing else”
    Key Vault Secrets User on that secret    1.2.3
  • “keys protected by HSMs; nobody may permanently delete”
    Premium SKU + purge protection    1.2.2
  • “app uses the URI with no version; old value restorable”
    New version, then disable the old one    1.2.5
  • “plaintext secrets on VM disks, AWS too, nothing installed”
    Agentless secret scanning (Defender CSPM or Servers Plan 2)    1.2.6
  • “no deployment failed, compliance still 40%”
    Deny only stops new requests: Modify or DeployIfNotExists + remediation    1.3.1
  • “ReadOnly lock broke an app that only reads blobs”
    Listing keys is a POST; ReadOnly blocks it    1.3.4
  • “which PCI DSS controls are we failing?”
    Regulatory compliance, after adding the standard    1.3.2
  • “stays visible, reason recorded, ends on its own”
    Exemption with an expiry date    1.3.3
  • “Owner at the management group, Reader at the subscription”
    Still Owner: assignments add up    1.3.5
  • “Resource Guard owned by the same administrator”
    Multi-user authorization stops mistakes, not a rogue admin    1.3.8
  • “must never be created, whatever tool deploys it”
    Azure Policy with Deny    1.3.9
